Getting Started

Welcome to NexaKS! This guide will walk you through everything you need to activate and use your license key.

What You Need

  • A NexaKS license key (format: NXKS-XXXX-XXXX-XXXX-XXXX) from an authorized reseller or admin
  • A Discord account
  • An invite to the NexaKS Discord server
Note: Your key is tied to a specific project (Macro, Premium, or Private). Make sure you know which project you purchased so you know which script you will get access to.

Redeeming Your Key

There are two ways to redeem your key. Both work exactly the same way and take less than 30 seconds.

Option 1: Using the Discord Panel (Recommended)

  1. Go to the NexaKS Discord server
  2. Find the channel with the NexaKS panel (usually pinned or in a dedicated channel)
  3. Click the green Redeem Key button
  4. Paste your license key in the popup and click Submit
  5. Done! You will get an activation confirmation with your plan details and expiration date

Option 2: Using the Slash Command

You can also redeem directly with a slash command anywhere on the server:

/redeem key: NXKS-XXXX-XXXX-XXXX-XXXX
What happens after redemption:
  • Your Discord account gets the Verified role automatically
  • You get the project role for your purchase (Macro, Premium, or Private)
  • The bot links your Discord account to your license so you can DM commands
  • You can now request your loader script

Getting Your Script

After redeeming, you need to get your personalized loader script to run in Roblox.

Getting the Loader

  1. On the panel, click the orange Get Script button (or type /loader)
  2. The bot will send you a private DM with your loader code
  3. Copy the loader code exactly as sent
  4. Open your Roblox executor
  5. Paste the loader and click Execute
WARNING: Your loader contains your personal key. Never share it publicly. Sharing your loader or key will result in your license being revoked and possibly a permanent ban.

First Time Running the Script

The first time you run the loader, it will bind to your current device (HWID). This means the script will only work on this exact device from now on. If you want to use a different device, you need to reset your HWID first.

Managing Your HWID

HWID (Hardware ID) is what locks your key to a specific device. This prevents key sharing and protects your license.

Resetting Your HWID

You can reset your HWID if you want to switch devices or reinstall your OS. Two ways to do it:

  • Click the red Reset HWID button on the panel
  • Type /resethwid anywhere on the server
HWID Reset Rules:
  • 15-hour cooldown between resets
  • 5 total resets per key (contact admin if you need more)
  • The first reset becomes available 15 hours after you first redeem your key

After Resetting

Once you reset, just run your script again on the new device. It will automatically bind to the new HWID.

Troubleshooting

"Invalid license key"

Make sure you copied the key correctly. Keys start with NXKS- and have four groups of four characters separated by dashes. No spaces, and it is not case-sensitive.

"Already Claimed"

This key is already linked to another Discord account. Keys can only be used by one person. If you believe this is an error, contact an admin.

"Hardware ID mismatch"

You are trying to use your key on a different device than the one it is bound to. Use /resethwid first, then run the script again on the new device.

"Cooldown Active"

You already reset your HWID within the last 15 hours. Wait for the cooldown to pass, then try again.

"Limit Reached"

You have used all 5 HWID resets for your key. Contact an admin to request additional resets or a new key.

DMs are closed

If the bot cannot DM you the loader, enable "Allow direct messages from server members" in your Discord privacy settings. If DMs are closed, the loader will be shown in the same channel (visible only to you).

Script does not run

Make sure you copied the entire loader code, including the last line. Try again with a fresh copy from /loader. If it still fails, check if your executor supports HttpGet.

Need more help? Open a support ticket in the Discord server or contact an admin directly.

Overview

As an admin, you have access to the full management system: create projects, generate license keys, manage users, monitor system health, and control script distribution.

Your workflow revolves around three main areas:

  • Website Admin Panel - full data management, bulk operations, analytics
  • Discord Bot - quick actions, on-the-go management, direct user interaction
  • Supabase Dashboard - direct database access for advanced operations (rare)
Rule of thumb: use the website for bulk operations (generating 50 keys, viewing analytics) and Discord for quick fixes (revoking one key, checking one user).

Managing Projects

A project is a container for a specific script product. Each key you generate can be tied to one project, which determines what script the user gets access to.

Current Projects

NexaKS uses three project slugs, each mapped to a Discord role:

  • macro - Macro role
  • premium - Premium role
  • private - Private role

When a user redeems a key tied to a project, they automatically get the matching role on Discord. This lets you separate access channels, script versions, and features per tier.

Creating a New Project

On Discord:

/project create slug: newproject name: New Project Display Name

On the website: go to Projects, click Create Project, enter slug (lowercase, no spaces) and display name, then configure settings.

Important: If you create a new project, you also need to add its role ID to bot.js in the PROJECT_ROLE_MAP constant, otherwise auto-role assignment will not work for it.

Viewing and Deleting Projects

/project list
See all projects and their slugs
/project delete slug: X
Delete a project (existing keys are not deleted)

Generating Keys

Keys are the currency of your business. Two ways to generate them:

Via the Website (Recommended for Bulk)

  1. Go to the admin panel
  2. Click Generate Keys in the sidebar
  3. Set the parameters:
    • Quantity - how many keys (1-500)
    • Duration - 1 day, 7 days, 30 days, 90 days, 1 year, or Lifetime
    • Plan - Free, Pro, or Enterprise
    • HWID Reset Limit - default 5, adjust as needed
    • Project - which project the key belongs to (Macro/Premium/Private)
  4. Click Generate Keys
  5. A .txt file with your generated keys will automatically download

Via Discord (Quick Single Keys)

/key create plan: pro duration: 30 quantity: 1 project: macro

The bot will reply with the generated keys, ready to copy and send to customers.

Tip: When generating in bulk (10+), always use the website - the .txt file makes distribution easier and you have a record.

Extending, Revoking, and Deleting Keys

/key extend key: NXKS-... days: 30
Add days to a key's expiry (renewals)
/key revoke key: NXKS-...
Revoke a key (user loses access immediately, key stays in DB)
/key delete key: NXKS-...
Permanently delete a key from the DB
/key info key: NXKS-...
View full details of a key (owner, plan, expiry, HWID, executions)

Key Distribution

Once you have generated keys, here is the recommended workflow for distributing them to buyers.

Standard Sale Flow

  1. Customer contacts you - via GCash, Discord DM, page, or wherever you accept orders
  2. Confirm payment - always verify payment before sending the key
  3. Generate the key - use /key create with the correct project (Macro/Premium/Private) matching what they bought
  4. Send the key - DM it to the customer with instructions to redeem via /redeem or the panel
  5. Log the sale - keep a record (Excel, Notion, whatever works) linking the key to the customer

Bulk Reseller Distribution

If you have resellers or partners:

  1. Generate a batch of keys (e.g., 20 Pro/30-day/Macro keys) via the website
  2. Download the auto-generated .txt file
  3. Send the .txt file to your reseller securely (private channel, encrypted, etc.)
  4. Reseller distributes to their customers
  5. Track which keys went to which reseller (batch by date/naming convention)
Security warnings:
  • Never post keys in public channels
  • Never send keys via unencrypted screenshots
  • If a key is leaked, revoke it immediately with /key revoke
  • Rotate reseller batches (do not reuse the same batch for multiple resellers)

Managing Users

You have full control over the user base. Common admin actions:

Looking Up a User

/user info user: @someone

Shows their profile: total keys, active/revoked counts, admin status, ban status.

Blacklisting a User

Use this if a user is abusing the system (sharing keys, harassment, etc.):

/user blacklist user: @someone reason: Key sharing

This will:

  • Mark the user as banned in the database
  • Automatically revoke all their active keys
  • Prevent them from using any script bound to their account
  • Log the action for accountability

Removing a Blacklist

/user unblacklist user: @someone

This only unbans them. Their revoked keys stay revoked - you need to issue new keys separately.

HWID Admin

Users can reset their own HWID (with cooldown and limit), but as admin you can force-reset for anyone:

/hwid reset user: @someone

This:

  • Bypasses the 15-hour cooldown
  • Restores their reset counter to 0/5
  • Clears their bound HWID (they can use a new device immediately)
When to use: Only when the user has a legitimate reason (bought a new PC, hardware died, reinstalling OS). Do not use casually - the limits exist for a reason.

Analytics

The analytics page shows real-time metrics:

  • Daily Activity - key activations and executions over the last 30 days
  • Keys by Status - how many active, unclaimed, revoked, expired
  • Keys by Plan - Free vs Pro vs Enterprise distribution
  • Keys by Project - which projects are selling most
  • HWID Resets - reset activity trend (spot abuse patterns)
  • Top Users and Top Keys - most active accounts and heaviest-used keys

Data auto-refreshes every 60 seconds. Use the Refresh button for instant reload.

What to Watch For

  • Sudden spike in HWID resets = possible key sharing attempt (investigate that user)
  • High executions on a single key = healthy usage, or key is being shared - check with /key info
  • Activations drop to zero = check bot status, sales channel issues

Managing Scripts

Scripts are stored per-project in the project_scripts table. You can publish different scripts for different plans (e.g., Pro users get more features than Free users).

Updating a Script

  1. Go to the admin panel
  2. Click Scripts in the sidebar
  3. Select the project and plan you want to update
  4. Edit the Lua content in the textarea
  5. Set the status to Published
  6. Save

All active users will get the new script on their next execution - no need to reissue keys.

Keyless Scripts

If you want a script to run without a key (e.g., a free demo), enable the Keyless flag on that script. Users can access it without any HWID binding.

Test before publishing: Set the script to draft status first, test with your own account, then flip to published once it works.

Best Practices

Security

  • Never share your admin login credentials
  • Use a strong password for your Supabase account
  • Do not commit environment variables (bot token, service keys) to Git
  • Revoke leaked keys immediately - do not wait
  • Rotate reseller batches to isolate leaks

Data Hygiene

  • Delete truly abandoned keys periodically (unclaimed for 90+ days)
  • Keep audit logs for at least 30 days for investigations
  • Back up your Supabase database monthly (Settings then Backups)

Customer Service

  • Respond to support tickets within 24 hours
  • When in doubt, use /user info to check the user's history before responding
  • For legitimate HWID reset requests beyond the 5 limit, offer to force-reset once - not repeatedly
  • Track customer complaints in a spreadsheet to spot recurring issues

Growth

  • Monitor the analytics page weekly to spot trends
  • Keys by Plan tells you which tier to promote more
  • Keys by Project shows demand - consider new projects for high-interest niches
  • Top Users list = your best advocates - engage with them
Final tip: The system is designed to be self-service for users. Your job as admin is to keep it running smoothly, watch for abuse, and handle the exceptions. Trust the automation for the routine stuff.
